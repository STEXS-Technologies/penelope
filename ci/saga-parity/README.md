# Independent saga consumer parity

Run `./scripts/check-saga-machine-parity.sh` from the repository root. CI runs
this on stable and Rust 1.89. The default fixture uses only frozen 0.4 facade
paths. Feature `prepared` selects the new canonical saga preparation adapters and
common inspection trait, with the same inputs and observations.

`baseline/v0.4.0.jsonl.gz` was generated by compiling this exact fixture without
`prepared` against unmodified library sources at
`42ec187c9adfc7403b06215f405f2575f53c35c2`. This was an external consumer with
resolved dependencies pinned in `baseline/Cargo.lock`; it isolates library-source
compatibility and does not replace the original workspace qualification campaign.
The manifest binds source fixture and output hashes. Do not regenerate expected
observations using the candidate library.

There are 3,136 observations across 196 deterministic linear/graph histories.
They include successful decisions, typed failures, ordered actions and replay
records. Every successful prefix is replayed and checked against its projection.
The complete corpus includes all six saga statuses, unknown outcomes, compensation,
manual resolutions, timed retries, malformed definitions, missing edges and graph
visit limits. It is bounded differential evidence, not exhaustive saga validation;
existing property, wire, scope, action identity and crash tests remain required.

To reproduce the baseline independently, make a temporary Cargo package with this
manifest and source, point only its `penelope` dependency at the 0.4 checkout,
copy `baseline/Cargo.lock`, and run without `prepared`. Compare stdout byte for
byte with the decompressed corpus. Current legacy and prepared outputs must both
match that corpus; serialization changes cannot be hidden by changing both paths.
